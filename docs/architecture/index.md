# Архитектура

Текущий Cargo workspace разделяет библиотеку движка и исполняемое приложение.

## Текущая структура

```text
raggie/
├── Cargo.toml
├── Cargo.lock
├── rust-toolchain.toml
├── Makefile
├── apps/
│   └── raggie-cli/
├── crates/
│   └── raggie-engine/
└── docs/
```

Корневой `Cargo.toml` описывает виртуальный Cargo workspace без корневого
пакета. Workspace состоит из двух пакетов:

- `apps/raggie-cli` — минимальное исполняемое приложение и будущий интерфейс
  командной строки;
- `crates/raggie-engine` — библиотека движка без предметного API.

Оба пакета наследуют поля `version`, `edition`, `rust-version`, `repository`
и `publish`, а также lint-настройки workspace. Каталог `docs/` содержит
документацию текущей версии, которую собирает MkDocs.

## Граница компонентов

`apps/raggie-cli` зависит от `crates/raggie-engine` через локальную
Cargo-зависимость. Обратной зависимости нет.

Следующие задачи этапа добавят в библиотеку правила коллекции, записей,
валидации и поиска. CLI будет отвечать за разбор внешнего ввода и вывод
результата. Библиотека останется независимой от приложения, сетевого
транспорта, рабочей директории и оркестратора.

## Правила роста

- Запускаемые программы размещаются в `apps/`.
- Библиотеки с устойчивой ответственностью размещаются в `crates/`.
- Приложения могут зависеть от библиотек; библиотеки не зависят от приложений.
- Новый crate создаётся после появления отдельной ответственности и понятного
  направления зависимостей.
- Каталоги `common`, `shared`, `utils` и `helpers` не используются как свалки.
- Автоматизация добавляется для существующих команд и проверок.
- Эксплуатационные файлы появляются вместе с серверным контуром.
