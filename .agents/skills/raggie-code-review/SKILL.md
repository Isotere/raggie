# Ревью Raggie

Ревью отделено от реализации. Не меняй файлы, не создавай commits и не отправляй GitHub review без прямого запроса.

## Порядок работы

1. Определи объект ревью: рабочее дерево, staged diff, commit, ветка или PR.
2. Прочитай связанную issue, документ текущего этапа и изменённые файлы.
3. Изучи diff в контексте вызывающего кода, тестов и публичных контрактов.
4. Запусти относящиеся к изменению проверки, если они доступны.
5. Сопоставь поведение с критериями issue или этапа.

## На что смотреть

В первую очередь ищи:

- ошибки корректности и регрессии;
- потерю, повреждение или молчаливое неверное прочтение данных;
- недетерминированный порядок результатов;
- неверную обработку размерности, `NaN`, бесконечности, переполнения и сравнения `f32`;
- расхождение точного поиска с зафиксированным эталоном;
- нарушение семантики вставки, замены, удаления и идентификаторов;
- смешение логической записи, физического формата и индекса;
- необоснованные заявления о durability или recovery;
- ошибки версионирования, проверки границ и совместимости долговечного формата;
- проблемы владения, времени жизни и конкурентного доступа;
- необоснованный `unsafe` и недокументированные инварианты;
- несовместимость публичного API;
- тесты, которые не закрепляют изменённое поведение;
- benchmark без воспроизводимых условий или выводы без измерений;
- секреты, PII, закрытые данные, абсолютные локальные пути и материалы с несовместимой лицензией.

Проверяй только свойства текущего этапа. Не требуй будущего ANN, хранения, сервера или cloud-инфраструктуры от раннего среза. Не требуй абстракций, patterns или разбиения на crates без конкретной проблемы.

## Формат результата

Сначала перечисли замечания по убыванию серьёзности. Для каждого укажи:

- файл и строку;
- наблюдаемую проблему;
- последствие;
- направление исправления без готового кода, если пользователь его не просил.

После замечаний перечисли открытые вопросы и выполненные проверки. Если существенных проблем нет, скажи это прямо и укажи, что не удалось проверить.

Отправляй комментарий или решение review в GitHub только по прямому запросу.
